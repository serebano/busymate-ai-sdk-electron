# Identity and authentication

Electron uses the v2 `BusymateBridge` only: the frozen kit v2 Electron files (`core/busymateBridgeCore.js`, `electron/main.js`, `electron/preload.js`, build 2.0.0), shipped byte-for-byte under `frozen/v2/2.0.0/`. Install exactly one identity bridge per chat WebContents before the first load. `createBusymateChatWindow` / `createBusymateChatView` do this for you; `installBusymateBridge(webContents, config)` is the bare bridge.

The transport is Electron IPC on channel `busymate:bridge`. The preload exposes `window.BusymateBridge` with `postMessage(string)` and `addEventListener("message", …)` through `contextBridge`, the same object shape the Android WebView injects. The main process authorises each message by the **sending frame's own security origin** (`event.senderFrame.origin`; `"null"` for a sandboxed frame), never by the window URL, and only for messages whose `event.sender` is the chat WebContents. The allow-list is exact: `https://<assistant>.busymate.ai` plus your exact `https` origins. Other origins get `denied` and your mint is never called.

Your authenticated backend mints a fresh single-use launch assertion for each `mint` call. Never cache or reuse a token/nonce pair. Never put a signing key, Busymate admin key or service-role credential in the app (including the main process: an Electron app is extractable). Use your existing authenticated HTTPS backend API. `mint(request)` resolves `{ token, nonce }`, resolves `null` when signed out, or rejects on failure (`mint_failed`). Preserve the nonce from the request; `request.assistant` and `request.origin` are set by the bridge, not by the page, so your backend may bind the token to them. The bridge gives up after 15 seconds (`timeout`). Do not invent a public Busymate mint endpoint: implement your tenant's endpoint using the official [identity guide](https://busymate.ai/docs/guides/identity-backend-signing).

`account` is a synchronous function returning your current account ID or `null`. The bridge sends only SHA-256(`appId:account`) truncated to 128 bits. Call `chat.accountChanged()` after login, logout or account switching; hosted chat owns identity refresh and clearing. `onClose` dismisses your host; `onAction` handles a fixed app-owned set of actions and returns whether it handled one. Do not expose arbitrary native execution.

The chat's `open` op opens only `https` URLs, through `openExternal` (default `shell.openExternal`). Keep navigation restricted to your trusted chat origins: the helper blocks other top-level navigations and opens https targets in the user's browser instead of leaving the privileged bridge on an arbitrary page. Identity availability failures keep chat anonymous (`not_signed_in`, `mint_failed`, `unsupported`); never log tokens, nonces, raw account IDs or audio while troubleshooting. The helper's `onEvent` log carries op names, origins and decisions only.

The frozen bridge emits `resume` when you call `chat.resume()`; `createBusymateChatWindow` calls it when the window regains focus. It emits `restored` after reloading a crashed renderer.

The byte-frozen [v2 wire contract](../CONTRACT-v2.md) defines hello/state/mint/open/action, error envelopes, version negotiation and events. Its no-new-permissions statement applies to the identity bridge alone. The optional microphone adapter adds microphone access.

The example's backend client refuses redirects (`fetch(…, { redirect: "error" })`) so your app session credential is never forwarded elsewhere. Configure the final HTTPS mint endpoint directly. Demo identity controls change the account reader only; your own app authentication and backend session logout remain your responsibility.
