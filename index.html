Busymate AI SDK for Electron

Busymate AI hosted chat in a secure Electron BrowserWindow or WebContentsView, with the frozen identity bridge and a tap-triggered microphone adapter.

What it does

@busymate/ai-electron ships the frozen identity bridge (core, main and preload byte-identical to https://busymate.ai/sdk/v2/2.0.0/electron/), the microphone adapter for Electron, and a main-process helper that creates the chat window with secure defaults: contextIsolation, the Chromium sandbox, no Node.js integration, exact-origin navigation and denied window.open.

Secure chat host

createBusymateChatWindow gives you a BrowserWindow or WebContentsView on a dedicated persist:busymate-chat session, pinned to your exact origins.

Identity bridge v2

Your account() and mint(request) callbacks run in the main process; the preload exposes only the frozen bridge to the page.

Renderer recovery

When the renderer dies the frozen bridge reloads the chat and sends restored; your onRenderProcessGone callback is told too.

Example app

The example app consumes the package (file:..): a Settings window configures the chat, identity mode and microphone, and opens the hosted chat window.

Install

The package is not on the npm registry; install the packed tarball attached to the release, or build from the tag.

  1. Install the release tarball.

    npm install https://github.com/serebano/busymate-ai-sdk-electron/releases/download/1.0.1/busymate-ai-electron-1.0.1.tgz

  2. Or pin the git tag and build it locally.

    git clone --branch 1.0.1 --depth 1 https://github.com/serebano/busymate-ai-sdk-electron.git vendor/busymate-ai-sdk-electron
(cd vendor/busymate-ai-sdk-electron && npm ci && npm run build)
npm install ./vendor/busymate-ai-sdk-electron

  3. Create the chat window from the main process once the app is ready.

    const { createBusymateChatWindow } = require("@busymate/ai-electron");
const chat = createBusymateChatWindow({
  url: "https://acme.busymate.ai/?channel=desktop_sdk",
  assistant: "acme",
  account: () => session.userIdOrNull,
  mint: (request) => backend.mintBusymate(request),
  onClose: () => chat.window.close(),
});
chat.load();

Identity linking and the microphone

Both bridges are installed by your app before the chat's first load. Your native app release is what installs or upgrades native SDK code; the hosted chat updates independently.

Identity linking

BusymateBridge (wire v2, build 2.0.0) asks your main process for the current account and for a fresh assertion minted by your authenticated backend; null means signed out and nothing is fabricated. Read identity.md.

Microphone

BusymateMicrophone (wire 1, adapter 1.0.0) asks the OS only on the user's tap (systemPreferences.askForMediaAccess on macOS) and the session permission handler grants audio only for allowed origins. Packaged macOS apps need NSMicrophoneUsageDescription and the audio-input entitlement. Read microphone.md.
